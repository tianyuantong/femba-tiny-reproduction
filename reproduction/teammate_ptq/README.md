# 上游仓库模型的 int8 对比：FP32 / PTQ / QAP

模型与 QAP 方法来自上游仓库 [berumottovv00/BioFoundation](https://github.com/berumottovv00/BioFoundation)。

**结论**：在上游仓库的模型和 TUAR 数据上压缩到 8 位，“训练时就带着压缩”（QAP）基本不掉分，“训完再压缩”（PTQ）掉了一截。三个随机种子的结果一致。

| 模型 | AUROC（三个种子平均） | 比 FP32 |
| --- | ---: | ---: |
| FP32（不压缩） | 0.9045 | — |
| QAP int8（上游仓库的方法） | 0.9021 | −0.0024 |
| PTQ int8（训完再压缩） | 0.8707 | −0.0338 |

- **QAP 比 PTQ 高约 0.03**，三个种子都是 QAP 更高。
- **PTQ 的输出整体偏向“有伪迹”**：测试集里真正有伪迹的占 54%，但用默认判断线时，PTQ 把 80%–100% 的样本都判成有伪迹；只用验证集重新选判断线后，平衡准确率回到约 77%（FP32 约 83%）。
- **C 组**（先正常预训练，最后带着压缩微调）：0.875，接近 PTQ。说明关键在于预训练阶段就带着压缩。目前只有一个种子。

**适用范围**：只测了 TUAR 一个任务；数据按录音划分，不是按人；模型完全沿用上游仓库的代码。

## PTQ 是怎么做的

PTQ 不再训练，只给训练好的 FP32 模型定好“刻度”，再用 8 位运行：

1. **权重**：每个权重张量用一个刻度，按这个张量里绝对值最大的数来定，正负对称（8 位取 −127 到 127）。刻度直接从权重算出来，不需要数据。
2. **激活**（中间计算结果）：共 35 个位置，每个位置一个刻度。用 512 个固定的训练窗口跑一遍，统计每个位置的数值范围，按某个百分位定刻度，超出的部分直接截掉。
3. **百分位怎么选**：试 7 档（99.999、99.99、99.9、99、98、95、90），只看验证集，挑 AUROC 最高的一档，选定后才跑测试集。三个种子分别选出 95、99.9、95。
4. **保持不变的部分**：权重本身一个数都不改；Mamba 内部的递推、归一化层和偏置保持浮点；深度卷积的权重按上游代码原样不量化。

## 用这套流程跑 int4 / 三值

1. **先定这一档指什么**：比如 int4 是只把权重压到 4 位、激活保持 8 位，还是两者都压到 4 位；三值还要定怎么映射成三档，沿用默认的按最大值定刻度会让绝大多数权重变成 0。PTQ 和同一档的 QAP 必须用同一套设置，结果才能比。
2. **取代码**：取上游仓库的[固定版本](https://github.com/berumottovv00/BioFoundation/tree/a2a4d441485efd8423c44b35d7448a30ccd44437)，打上 [`source.patch`](source.patch)。补丁只加了量化开关和校准函数，不改模型结构。
3. **改掉写死的 8 位**，一共三处：
   - 上游仓库的 `ARES/tests/test_networks/test_25_femba_tiny_int8.py` 里 `bit_width = 8`，权重和激活共用这一个值，要拆成两个参数；
   - `source.patch` 里 `models/femba_ptq.py` 的 `_quantizer_scales`，遇到不是 8 位的量化器会报错；
   - [`evaluate.py`](evaluate.py) 的 `quantization_contract`，会检查每个量化器都是 8 位。
4. **复用 FP32 模型**：PTQ 用的 FP32 模型和位宽无关，三个种子的 FP32 检查点可以直接拿来校准，不用重训。检查点不在仓库里，需要时找仓库维护者。
5. **按 [TRAINING.md](TRAINING.md) 跑校准和评估**：百分位要按新位宽在验证集上重新选一遍。
